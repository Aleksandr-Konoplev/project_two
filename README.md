# HeadHunter вакансии
Приложение для получения при помощи API сервиса платформы HeadHunter вакансий и записи их в файл, а также имеет методы их сортировки

## Модуль "classes_vacancy"

### Класс Vacancy

Класс Vacancy инициализирует объект вакансии используя данные из json ответа с атрибутами: name, url, salary, requirement. Также имеет метод init_vacancy_manual_method для ручной инициализации объекта передав данные атрибутов в ручном режиме.

#### Атрибуты:

- name: str (название вакансии)  
- url: str (ссылка на вакансию)
- salary: int (зарплата)
- requirement: str (краткое описание вакансии)

### Класс VacancyList

Класс VacancyList инициализирует объект с атрибутом vacancy_list, который является списком объектов класса Vacancy. Класс имеет методы для добавления вакансий и их сортировки

#### Методы:

- `add_one_vacancy` - Добавляет один элемент класса Vacancy в список vacancy_list
- `add_several_vacancy` - Добавляет список элементов класса Vacancy в список vacancy_list
- `add_one_vacancy_from_hh` - Добавляет один элемент в список vacancy_list из json ответа вызывая класс Vacancy
- `add_several_vacancy_from_hh` - Добавляет список элементов в список vacancy_list из списка json ответов вызывая класс Vacancy в цикле
- `add_vacancy_manual_method` - Добавляет один элемент в список vacancy_list принимая значения атрибутов от пользователя, используя Vacancy.init_vacancy_manual_method
- `sorted_by_salary` = Сортирует список вакансий по зарплате

## Модуль "classes_api"

Модуль `classes_api` реализует взаимодействие с API сервиса HeadHunter.  
Содержит абстрактный базовый класс `VacancyAPI`, определяющий интерфейс для получения вакансий,  
и конкретный класс `HeadHunterAPI`, реализующий этот интерфейс для API HeadHunter.

### Класс VacancyAPI

Абстрактный класс, задающий шаблон для классов, работающих с API вакансий.  
Служит основой для последующих реализаций (например, HeadHunterAPI).

#### Методы:

- **get_vacancies(query: str, area: int = None, per_page: int = 10) → list[dict]**  
  Абстрактный метод, который должен быть реализован в наследниках.  
  Определяет логику получения вакансий по ключевому слову.  

  **Параметры:**  
  - `query`: `str` — ключевое слово для поиска вакансий (например, `"Python"`)  
  - `area`: `int` — ID региона (например, `1` — Москва)  
  - `per_page`: `int` — количество вакансий, возвращаемых за один запрос (по умолчанию `10`)  

  **Возвращает:**  
  - `list[dict]` — список словарей, каждый из которых содержит данные о вакансии  
    (название, зарплату, ссылку, описание и т.д.)

### Класс HeadHunterAPI

Класс `HeadHunterAPI` — конкретная реализация базового класса `VacancyAPI`,  
предназначенная для работы с публичным API платформы [hh.ru](https://hh.ru).

#### Атрибуты:

- **BASE_URL**: `str` — базовый URL для обращения к API вакансий HeadHunter  
  (`"https://api.hh.ru/vacancies"`)

#### Методы:

- **get_vacancies(query: str, area: int = None, per_page: int = 10) → list[dict]**  
  Выполняет запрос к API HeadHunter для получения списка вакансий по ключевому слову.  
  Метод фильтрует результат, возвращая только список вакансий без лишней информации.

  **Особенности работы:**  
  - Если `per_page > 100` или `per_page < 1`, метод автоматически ограничивает значение до `100`.  
  - Можно передать параметр `area` (ID региона) для фильтрации по географии.  
  - При ошибке запроса выбрасывается исключение `ConnectionError` с кодом и текстом ошибки.

  **Возвращает:**  
  - `list[dict]` — список словарей, содержащих данные о найденных вакансиях.

- **__request_vacancies(params: dict) → list[dict]**  
  Приватный метод, выполняющий HTTP-запрос к API HeadHunter.  
  Не предназначен для вызова пользователем напрямую.

  **Логика работы:**  
  - Отправляет `GET`-запрос на `BASE_URL` с переданными параметрами.  
  - Проверяет успешность запроса (`status_code == 200`), иначе выбрасывает `ConnectionError`.  
  - Возвращает содержимое ключа `'items'` из JSON-ответа API.

## Модуль "classes_file_operations"
Модуль `classes_file_operations` предназначен для работы с файлами и сохранения данных о вакансиях.  
Он позволяет сохранять вакансии в формате JSON, добавлять новые вакансии, удалять существующие и искать вакансии в файле.  
Модуль работает с объектами классов `Vacancy` и `VacancyList` из модуля `classes_vacancy`.

### Класс ConnectFile
Абстрактный базовый класс для работы с файлами вакансий.  
Определяет интерфейс для операций с файлами: сохранение, добавление, удаление и поиск вакансий.

#### Методы:
- **save_vacancies_to_file(vacancy_list, file_name)**  
  Абстрактный метод для сохранения списка вакансий в новый файл.

- **add_vacancy_to_file(vacancy, file_name)**  
  Абстрактный метод для добавления одной вакансии в существующий файл.

- **add_vacancy_list_to_file(vacancy_list, file_name)**  
  Абстрактный метод для добавления списка вакансий в существующий файл.

- **del_vacancy_from_file(vacancy, file_name)**  
  Абстрактный метод для удаления вакансии из файла.

- **search_vacancy()**  
  Абстрактный метод для поиска вакансии в файле.

### Класс JSONSaver
Конкретная реализация класса `ConnectFile` для работы с файлами в формате JSON.

#### Методы:

- **save_vacancies_to_file(vacancy_list_obj, file_name)**  
  Сохраняет список вакансий, полученный в виде объекта `VacancyList`, в новый JSON-файл.  
  Каждая вакансия сохраняется как словарь с ключами: `id`, `name`, `url`, `salary`, `requirement`.

- **add_vacancy_to_file(vacancy, file_name)**  
  Добавляет одну вакансию в JSON-файл.  
  Если файл отсутствует, создается новый.  
  При добавлении проверяется корректность существующего JSON.

- **add_vacancy_list_to_file(vacancy_list, file_name)**  
  Добавляет несколько вакансий из объекта `VacancyList` в JSON-файл.  
  Создает файл при его отсутствии или добавляет к существующим данным.

- **del_vacancy_from_file(vacancy, file_name)**  
  Удаляет вакансию из JSON-файла по совпадению ссылки `url`.  
  Предусмотрена проверка наличия файла и корректности данных.

- **search_vacancy()**  
  Заготовка метода для поиска вакансии в файле (реализация отсутствует).

## Тестирование

Для проверки корректной работы модулей используются unit-тесты с библиотекой **pytest**.  
Тесты покрывают следующие сценарии:

### 1. Тесты для модуля `classes_api` (HeadHunterAPI)
- Проверка корректного получения вакансий из API по ключевому слову.
- Проверка добавления параметра `area` в запрос.
- Проверка обработки ошибок запроса (например, `ConnectionError` при ответе 500).
- Мокирование вызова `requests.get` для имитации работы API без реальных сетевых запросов.

### 2. Тесты для модуля `classes_file_operations` (JSONSaver)
- Проверка сохранения списка вакансий в новый JSON-файл.
- Проверка добавления одной вакансии и списка вакансий в файл.
- Проверка удаления вакансии по `url`.
- Проверка обработки ошибок: файл отсутствует, некорректный JSON, удаление несуществующей вакансии, передача неверного типа данных.

### 3. Тесты для модуля `classes_vacancy`
- Проверка инициализации объекта `Vacancy` из словаря API или вручную.
- Проверка корректности расчёта зарплаты (`from`, `to`, `None`).
- Проверка работы сеттеров `salary` и `requirement` с корректными и некорректными значениями.
- Проверка методов `VacancyList`:
  - добавление одной вакансии и нескольких вакансий,
  - добавление вакансий из словарей HH API,
  - сортировка вакансий по зарплате.
